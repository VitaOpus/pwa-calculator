# Валютный маршрут

PWA-приложение для расчёта цепочек валютных переводов. Позволяет задать сумму и последовательность валют (например, USD → RUB → KZT → TRY) и получить итоговую сумму с учётом актуальных курсов.

## Возможности

- Расчёт цепочки конвертаций через произвольное количество валют
- Поддержка 50+ валют со всего мира
- Актуальные курсы от внешнего сервиса (`calculator-service`)
- Работает как PWA — устанавливается на устройство, работает офлайн (закешированные данные)

## Локальная разработка

Требуется Node.js 22 или выше.

```bash
npm install
npm run dev
```

Приложение запустится на [http://localhost:5173](http://localhost:5173).

## Сборка и деплой

```bash
npm run build    # собрать продовую сборку в dist/
npm run preview  # локально просмотреть результат сборки
```

Деплой автоматизирован через GitLab CI:

- **merge request** → lint → сборка тест-образа → деплой на тест-сервер
- **`release/*`** → lint → сборка прод-образа → деплой на прод

Образ собирается через Kaniko и публикуется в GitLab Container Registry. На сервере поднимается через Docker Compose (`docker-compose.prod.yml`), раздаётся nginx.

## Архитектура кэширования и фоновых вычислений

### Service Worker (Workbox)

Приложение использует `vite-plugin-pwa` с двумя стратегиями кэширования:

- **Статические ресурсы** (JS, CSS, иконки) — `CacheFirst` с `max-age: 1 year`. Хэш в имени файла гарантирует обновление при новом деплое.
- **Курсы валют** (`/api/v1/rates`) — `StaleWhileRevalidate`: ответ отдаётся из кэша немедленно, параллельно в фоне уходит запрос на обновление. Кэш хранится 1 час — совпадает с серверным TTL.

`index.html` и `sw.js` отдаются с `Cache-Control: no-cache`, чтобы iOS и другие браузеры всегда проверяли наличие обновлений.

При возврате в приложение после часа отсутствия автоматически запускается рефетч курсов через событие `visibilitychange`.

### Web Worker (расчёт курсов)

Вычисление цепочки конвертаций (`convertCurrencyWithSteps`) выполняется в отдельном потоке через `calculate.worker.ts`, не блокируя главный поток и интерфейс. Общение с воркером построено на `postMessage` с числовым `id` для сопоставления запросов и ответов при параллельных вызовах. Результат сохраняется в Effector-стор через `calculateLocalFx.doneData`.
